# Реестр долга и находки аудита

Ведётся с 6 ноября 2026 года. Сюда записывается всё, что сознательно оставлено
недоделанным, и всё, что нашёл аудит. У каждой записи есть цена, то есть что
будет, если её не гасить, и выпуск, к которому её нужно погасить. Запись
закрывается коммитом, который её гасит, и тогда удаляется из этого файла.

Серьёзность: **высокая**: можно навредить игрокам или их данным,
**средняя**: ломается работа или проверка, **низкая**: неудобство
или будущая цена.

## Безопасность

### Б1. Задание на рендер берёт любое привязанное устройство (высокая)

`services/render_farm/http.py`: `_authorised` пропускает общий токен работника
и любой токен приглашения (`invites.known`). Значит, любой пользователь Dossier
с привязанным устройством может вызвать `/render/claim`, получить чужой
реплей и скин и вернуть произвольное видео, которое бот опубликует в беседе
от имени рендера.

Решение: список доверенных работников на сервере. Задания из бесед берут
только работники из списка. Устройство без допуска рендерит только задания
своего владельца, то есть реплеи, которые он сам отправил из приложения.
Перед публикацией в беседу сверять длительность видео с длиной реплея.

Совместимость: работники тестеров нужно внести в список до выкладки, иначе
ферма встанет. Ответ `hello` уже несёт поле `agree`, через него работник
без допуска узнаёт, почему ему не дают заданий.

Погасить: до 0.97.9, это изменение только на сервере.

### Б2. ffmpeg скачивается без проверки и запускается (высокая)

`native/src/ffmpeg.rs`: четыре сторонних сайта, ссылки вида «latest», хеш
не сверяется, после распаковки файл получает права на запуск. Подмена файла
на любом из сайтов даёт чужой код на машине игрока.

Решение: закрепить версии и SHA-256 каждой сборки в коде, а ещё лучше
выкладывать проверенные сборки ffmpeg в собственный релиз на GitHub и брать
их только оттуда. Ссылки «latest» убрать.

Цена компромисса: закреплённую версию придётся обновлять вручную.

Погасить: 0.98.0.

### Б3. Уязвимые зависимости (средняя)

`cargo deny check advisories` от 6 ноября:

- `rustls` 0.23.45: RUSTSEC-2026-0346, 0347, 0348, 0349;
- `rustls-webpki` 0.103.15: RUSTSEC-2026-0382;
- `webpki-roots` 1.0.9: RUSTSEC-2026-0381;
- `zip` 2.4.2: RUSTSEC-2026-0367, 0368, 0369, 0429. Затрагивают
  `ZipArchive::extract`, а его вызывает обновлятор (`updates.rs`, `unpack`).
  Остальная наша распаковка идёт через `enclosed_name` и этих путей не касается.

Решение: `cargo update` для TLS в пределах 0.23, переход `zip` на версию
с исправлениями, а в обновляторе своя распаковка, как в `maps.rs`, без
`extract`. Проверка `cargo deny` в CI на каждый пуш.

Без исправления остаются неподдерживаемые `paste`, `pin-utils`, `rustybuzz`,
`ttf-parser`, `zbus_names`, `zvariant`. Их тянут iced и wgpu, заменить их
можно только обновлением iced. Принимаем, пока iced не выпустит новую версию.

Погасить: 0.97.9 для TLS и обновлятора, 0.98.0 для проверки в CI.

### Б4. Ссылки открываются без проверки схемы (средняя)

`main_screen.rs`: `C::Open(url)` и `Effect::Open(url)` передают строку прямо
в `open::that`. Ссылки приходят с сервера и из пользовательских данных
(лента, пулы, профили). Ссылка `file://` или на схему другого приложения
откроет то, что игрок не просил. Лента новостей уже пропускает только
`http`, `https` и `mailto`, остальные места нет.

Решение: одна функция открытия ссылок, которая пропускает только `https`,
`http`, `mailto` и `osu://` (кнопка «Открыть в osu!» на столе баланса
открывает `osu://b/…`) и проверяет это тестом. Все вызовы `open::that` для ссылок идут
через неё.

Погасить: 0.97.9.

### Б5. Архивы карт распаковываются без предела (средняя)

`maps.rs`, `unpack`: архив с зеркала распаковывается целиком, без предела
числа файлов и общего размера. «Zip-бомба» с зеркала забьёт диск.
У скинов работника пределы уже есть (`SKIN_FILES_LIMIT`, `SKIN_EXPANDED_LIMIT`).

Решение: те же пределы для карт с запасом на видео в наборе.

Погасить: 0.97.9.

### Б6. Обновление проверяется только хешем из того же релиза (низкая)

Обновлятор сверяет архив с `SHA256SUMS`, который лежит в том же релизе.
От битой загрузки это защищает, от взлома аккаунта GitHub нет.

Решение: подписывать `SHA256SUMS` ключом, открытая часть которого зашита
в приложение (например, minisign). Ключ хранится вне GitHub.

Погасить: 0.100.0.

### Б7. Приложение на macOS не подписано целиком (средняя)

Сборка подписывает только исполняемый файл. Подпись `Dossier.app`
не сходится, и macOS называет приложение повреждённым.

Решение: `codesign --force --deep --sign -` в `release.yml`. Решить: покупать
ли Developer ID и заверять сборки у Apple.

Погасить: 0.97.9 для локальной подписи.

### Б8. Токен устройства хранится открытым текстом (низкая)

`settings.json` с правами 0600 на macOS и Linux, на Windows с правами
профиля по умолчанию. Копия папки профиля уносит токен.

Решение: связка ключей системы (Keychain, Credential Manager, Secret Service).
Цена: ещё одна зависимость и миграция настроек.

Погасить: не раньше 0.100.0, по решению владельца.

### Принятый риск: чтение памяти игры Witness

Поддержка osu! не одобрила чтение памяти. Владелец принял этот риск
23 октября 2026 года, Witness включается только переключателем. Здесь
это записано, чтобы не открывать вопрос заново.

## Процесс

### П1. CI не проверяет рабочую ветку (высокая)

`ci.yml` запускается на пуш в `global` и на pull request, а работа идёт
в `continuum`, которая на 6 ноября опережает `global` на 128 коммитов.
Релиз собирается с тега и тестов не запускает. Тесты идут только локально.

Решение: CI на каждый пуш в `continuum`, тег релиза ставится только
на коммит с зелёным CI.

Погасить: 0.98.0.

### П2. Вышедшую версию пересобирали под тем же номером (средняя)

6 ноября 0.97.8 пересобрали с исправлением. У кого старая 0.97.8, тем
автообновление новую не предложит.

Правило: любое исправление после выхода получает новый номер.

### П3. Шаги сборки без предела времени (низкая)

6 ноября `apt-get` в сборке релиза висел 35 минут.

Решение: `timeout-minutes` у задач и повтор установки пакетов.

Погасить: 0.97.9.

### П4. Галерея не видит части экрана (средняя)

Карточки ленты в галерее без обложек, поэтому кадры GPU не поймали пропажу
обложек 5 ноября. Эталоны листа подписки устарели и не обновлялись.

Решение: сцены с обложками в ленте, пересмотр устаревших эталонов
(новые PNG сначала просматриваются, тесты их не обновляют).

Погасить: 0.98.0.

### П5. Регрессии кэшей нашли люди, а не тесты (средняя)

Ограничение кэшей 5 ноября сломало аватарки и обложки, это нашли тестеры.

Решение: тесты на кэш кадров (`film.rs`, картинка дважды за кадр) и на кэш
картинок Сообщества, замер памяти за долгую сессию перед выбором пределов.

Погасить: 0.98.0.

## Код

### К1. Большие файлы экранов (низкая, растёт)

`main_screen.rs` 7896 строк, `ui.rs` 6364, `desk_screen.rs` 4100,
`gallery.rs` 2715, `pools_screen.rs` 2100. Каждая правка в них задевает
чужие экраны, а параллельные правки сталкиваются.

Решение: выносить экраны в модули только вместе с работой над ними и только
без изменения поведения, отдельным коммитом с прогоном тестов и галереи.
Большой разовый перенос не делаем: он рискует всем сразу.

### К2. Светлые края у картинок (средняя)

Всплывали 31 октября, 1 и 6 ноября. Причина каждый раз одна: в стопке
у затемнения и картинки под ним общий край, а iced берёт высоту стопки
по первому слою.

Решение: одна обёртка в `ui` для «картинка под затемнением», которая
укорачивает нижние слои, и замена ею всех таких стопок.

Погасить: 0.98.0.

### К3. Неподдерживаемые зависимости iced (низкая)

См. Б3. Ждём новую версию iced, своя копия `iced_wgpu` лежит в
`native/vendor` и при обновлении должна быть сверена заново.
